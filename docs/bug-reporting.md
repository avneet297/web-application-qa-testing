# Bug Reporting Guidelines

A good bug report should allow a developer to reproduce the problem without needing additional clarification.

## Bug Report Template

### Bug ID

BUG-XXX

### Title

Short description of the problem.

### Environment

* OS:
* Browser:
* Browser version:
* Device:
* Screen resolution:

### Severity

* Critical
* High
* Medium
* Low

### Priority

* P0 — Immediate
* P1 — High
* P2 — Medium
* P3 — Low

### Preconditions

Describe anything that must be completed before reproducing the issue.

### Steps to Reproduce

1. Step one
2. Step two
3. Step three

### Expected Result

Describe what should happen.

### Actual Result

Describe what actually happened.

### Evidence

Attach:

* Screenshot
* Screen recording
* Console error
* Network information where relevant

### Frequency

* Always
* Frequently
* Intermittent
* Once

### Suggested Severity Guidelines

**Critical**

Application crash, data loss, security issue, or complete blockage of a critical workflow.

**High**

Major functionality does not work and there is no reasonable workaround.

**Medium**

Functionality is affected but a workaround exists.

**Low**

Minor cosmetic or usability issue with limited user impact.
